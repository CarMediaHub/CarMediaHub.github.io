# 운영 서비스와 바인딩

상태: v0 초안

CarMediaHub는 미디어 및 네트워크 도구를 운영자가 관리하는 서비스로 취급합니다. 서비스는 Core와 같은 호스트에 설치할 수도 있고 운영자가 관리하는 다른 호스트에서 제공할 수도 있습니다. 플러그인은 플러그인마다 공개 포트를 열지 않고 제어된 서비스 바인딩을 사용합니다.

## 서비스 역할

- **AList**: 운영자가 관리하는 저장소의 파일 목록과 WebDAV 기능을 제공합니다.
- **rclone**: 저장소 공급자를 연결하거나 정규화하고 호환 서비스에 제어된 WebDAV 엔드포인트를 제공합니다.
- **FFmpeg**: 미디어 탐색, 리먹스 및 향후 재생 파이프라인의 처리 의존성입니다.
- **Mihomo** 및 유사 네트워크 도구: 운영자가 관리하는 네트워크 서비스이며 Core는 라우팅 정책을 정하지 않습니다.
- **Nginx 또는 동등한 게이트웨이**: 내부 컴포넌트 트래픽을 라우팅하는 데 사용할 수 있지만 모든 배포에 필수는 아니며 플러그인마다 공개 포트를 만들 필요도 없습니다.

이 서비스들은 호환 대상이자 관리되는 의존성입니다. CarMediaHub는 업스트림 소스 코드를 수정하지 않습니다. 호환 플러그인은 Core의 서비스 바인딩 API로 서비스를 연결하여 클라이언트가 하나의 CarMediaHub 진입점에서 사용할 수 있게 합니다.

Core 구성 요소 카탈로그는 선택과 설치 전 검사를 위한 제한된 역할을 기록합니다: 스토리지 서비스, WebDAV, 미디어 처리, 아카이브, 네트워크 egress. 역할은 메타데이터일 뿐 서명된 바이너리가 포함되었거나 설치되었다는 뜻이 아닙니다. 버전, 플랫폼, digest, 서명과 상태 확인은 별도의 게이트입니다.

공개된 `alist-web-bridge` 참고 어댑터는 이 경계를 보여 줍니다. 운영자가 승인한 AList 바인딩을 사용하고 제한된 상대 경로와 필터링된 헤더만 전달합니다. `GET`/`HEAD`는 상대 리소스를 읽고, `POST`는 `/api/fs/list`, `/api/fs/get`, `/api/fs/search`로 제한되며 JSON 본문은 64 KiB 이하입니다. AList 주소, 자격 증명, 쿠키 또는 업스트림 소스 코드는 포함하지 않습니다. 이 예제는 계약을 설명하기 위한 것이며 모든 AList WebDAV 또는 관리 기능을 지원한다는 의미는 아닙니다.

공개된 `mihomo-web-bridge` 참고 어댑터는 동일한 모델로 운영자가 승인한 Mihomo 제어 API를 연결하고 `/configs`, `/proxies`, `/providers`, `/rules`, `/connections`, `/version`과 같은 제한된 경로만 노출합니다. 첫 버전은 인증 헤더를 전달하거나 WebSocket 트래픽 패널을 제공하거나 Mihomo를 수정하지 않습니다. 이는 제어 API 호환 예제이며 전체 Clash Web UI를 지원한다는 의미가 아닙니다.

## 바인딩 모델

운영자는 설치된 특정 플러그인 인스턴스에 바인딩을 설정합니다. 바인딩에는 서비스 식별자와 내부 업스트림 주소가 포함되며 Core가 상태 확인, 요청 및 응답 크기, 동시성, 리디렉션 제한을 적용합니다. 플러그인은 capability 범위의 클라이언트를 받으며 원시 데이터베이스 연결, 임의 명령 실행, 호스트 환경 변수 또는 제한 없는 소켓을 받지 않습니다.

바인딩은 자동 검색 기능이 아닙니다. Core는 LAN을 검색하거나 `PATH`에서 값을 추론하거나 시스템 환경 변수를 암묵적으로 읽지 않습니다. 운영자가 관리 화면이나 배포 설정에서 엔드포인트와 자격 증명을 명시해야 하며, 비밀 값은 Core가 관리하는 자격 증명 경계 안에 보관됩니다.

## 일반적인 미디어 경로

```text
브라우저 또는 차량 클라이언트
  -> 하나의 CarMediaHub 진입점
  -> 플러그인 라우트
  -> 제어된 서비스 바인딩
  -> 운영자가 관리하는 AList/rclone/미디어 서비스
```

Core는 정상 상태의 관리되는 FFmpeg 구성 요소를 통해 제한된 remux/트랜스코딩 및 VOD HLS 작업을 실행할 수 있습니다. Worker와 Native/Docker 서비스 실행기는 별도의 배포 기준으로 관리됩니다. 현재 계약은 라이브 HLS나 모든 플랫폼용 AList/rclone/Mihomo 바이너리가 이미 제공된다는 뜻이 아닙니다.

## 운영 경계

- 바인딩 범위는 하나의 설치와 하나의 플러그인 인스턴스로 제한됩니다.
- 상태 확인은 명시된 안전한 엔드포인트만 사용하며 리디렉션과 응답 크기를 제한합니다.
- 바인딩 실패는 안정적인 진단 코드로 보고하고 업스트림 경로나 비밀 값을 노출하지 않습니다.
- 운영자는 업스트림 서비스의 라이선스, 자격 증명, 네트워크 정책, 저장소 권한과 보안을 책임집니다.
- 필수 바인딩을 사용할 수 없을 때 플러그인은 명확한 대체 상태를 표시해야 합니다.

## 현재 상태

Core의 서비스 바인딩 API, 설치 인스턴스 범위, 상태 확인, 요청/응답/동시성 제한 및 관리 화면 표현은 구현되어 테스트되었습니다. 실제 서드파티 바이너리의 Native/Docker 배포, 플랫폼별 복구와 프로덕션 미디어 파이프라인은 아직 계획 단계이며 자세한 기준은 거버넌스 저장소의 전체 로드맵에서 관리합니다.
