# 백업과 복구

상태: v0 초안

Core는 운영자가 관리하는 상태를 오프라인 스냅샷으로 저장하는 흐름을 제공합니다. SQLite 본체와 WAL 사이드카가 안정된 상태가 되도록 스냅샷을 만들기 전에 Core를 중지하세요.

## 스냅샷 만들기

Core 저장소 또는 배포 이미지에서 실행합니다.

```powershell
pnpm backup backup --data-dir .\data --output .\snapshots\cmh-01
```

스냅샷에는 SQLite 데이터베이스와 사이드카, 배포 서비스 키, 검증된 플러그인 패키지와 관리되는 컴포넌트 파일만 포함됩니다. 매니페스트는 각 파일의 크기와 SHA-256 다이제스트를 기록합니다.

대상은 데이터 디렉터리 밖에 있어야 하며 이미 존재해서는 안 됩니다. Core는 임시 디렉터리에 먼저 기록하고 모든 파일과 매니페스트가 완성된 뒤 원자적으로 이름을 바꿉니다.

## 검증과 복구

복구는 새 디렉터리에만 수행됩니다.

```powershell
pnpm backup restore --snapshot .\snapshots\cmh-01 --data-dir .\restored-data
```

복사 전에 Core는 매니페스트, 관리 경로 허용 목록, 모든 부모 디렉터리, 파일 형식과 크기 및 다이제스트를 검증합니다. 심볼릭 링크, 경로 탈출, 스냅샷 내부 대상과 이미 존재하는 대상 디렉터리는 거부됩니다. 복구된 배포를 시작하기 전에 구성과 자격 증명을 확인하세요.

## 책임과 제한

- 스냅샷은 원본 데이터 디렉터리와 분리해 저장하고 민감한 자격 증명처럼 보호하세요.
- 스냅샷에는 보호된 로컬 상태를 복호화하는 데 필요한 키가 포함되므로 공개 내보내기가 아닙니다.
- 현재 흐름은 로컬 오프라인 방식이며 데이터를 업로드하거나 예약 백업을 만들지 않고 온라인 핫 백업도 제공하지 않습니다.
- Docker 이미지 빌드, Native 설치 관리자, 플랫폼 간 복구 훈련, 보존 정책과 업그레이드 롤백은 별도의 출시 기준입니다.
