# 架构

状态：v0 草案

CarMediaHub 是自托管平台，运营者通过自己控制的基础设施，把经过授权的本地能力发布给浏览器和车载显示屏。

```text
浏览器或车载显示屏
  -> 运营者控制的入口
  -> CarMediaHub Gateway
  -> Core、Broker、Supervisor
  -> 隔离的插件运行时组
  -> 已授权的本地资源或获准网络目标
```

Core 是唯一的公开应用入口。插件注册逻辑路由并使用 SDK capability；插件不发布宿主公网端口，也不获得原始数据库凭据、不受限制的宿主路径、浏览器 Profile 数据或网络访问。

Gateway 提供进程内流保护：每个认证会话有并发流限制，每条流有累计字节预算。流量超出预算时，Core 会取消 Worker 请求并释放租约。该机制保护单个 Core 实例，不替代运营者的带宽限制或上游限流。

管理端测速同时测量下载和上传。上传测量只接受已认证用户发送的 `application/octet-stream`，大小限制为 64 KiB 至 2 MiB；Core 不持久化正文，只返回接收字节数。

## 运行时组

| 运行时组 | 适用范围 |
|---|---|
| 共享适配器宿主 | 低风险、轻量、请求模型兼容的适配器 |
| 独立 Worker | 浏览器、文件、网络、媒体、第三方、长时间或高资源任务 |
| WASM 模块 | 无任意系统访问、无长期连接的纯计算 |

安装插件不代表永久常驻进程。Supervisor 根据生命周期和资源策略启动、排空、停止、更新和恢复运行时组。

管理端会区分插件包安装状态和 Worker 健康状态。已安装的包仍可能处于停止、启动中、退避、停用或失败状态；面板只显示 Supervisor 状态和重试次数，不暴露宿主路径或秘密。

基础组件的 Check 只验证受管安装文件存在且 SHA-256 摘要匹配，不执行 AList、rclone、FFmpeg 等二进制，也不从系统 PATH 或环境变量发现组件。

同一页面会列出每个已校验 Manifest 声明的 capabilities 和当前安装实例的授权集合。安装时默认继承声明能力，运营者可以把授权收紧为声明集合的子集；Core 仍会在每次能力调用时按当前授权、安装实例和用户边界校验，授权变更会写入审计。

## 数据与身份

所有操作在适用时都带有 Deployment、Organization、User、Device/Session 和 Plugin Installation 作用域。平台提供逻辑私有数据访问；存储后端不会改变公开 SDK 行为。

## 部署边界

运营者选择域名、入口、网络路径、存储和带宽。Community 运行不要求 CarMediaHub 托管账号或中继。自托管不免除运营者对访问控制、网络可见性、内容权利和适用政策的责任。
