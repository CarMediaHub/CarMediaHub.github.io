# 诊断与故障排查

使用管理端判断故障属于 Core、插件、受管组件、上游绑定还是客户端浏览器。先执行影响最小的检查，并在每次报告中记录部署版本。

## 健康检查

- **存活**：Core 进程能够响应。
- **就绪**：数据库和启动所需状态可用。
- **组件健康**：已登记的受管组件通过摘要和健康检查。
- **插件状态**：显示有界状态和重试次数，不暴露 Worker 命令行或宿主路径。

Core 健康不代表上游存储、网络绑定或车机浏览器可以播放所有文件。

## 浏览器桥接检查

管理员可以查看已登记的逻辑浏览器目标和规范化 HTTPS Origin。浏览器任务应按顺序检查：会话仍有效、插件能力已授权、目标已登记、浏览器组件健康可用，最后查看任务结果或取消状态。过期会话和结果不可复用。

## 媒体检查

重试播放前先检查媒体来源、播放会话和可用模式。`direct-range`、转封装和转码是不同能力。缺少播放模式表示兼容性限制，不应通过本地命令或任意 URL 绕过 Core。

## 报告与隐私

报告应包含 Core、插件和组件版本、稳定诊断码、部署目标和时间戳。删除 Cookie、Token、凭据、浏览器 Profile、绝对路径、上游 URL 以及能识别私有内容的文件名。不要附加浏览器 Profile 或不受限制的调试压缩包。
