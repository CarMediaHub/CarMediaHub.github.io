# 服务绑定

状态：v0 草案

服务绑定让插件通过 CarMediaHub 单一入口使用运营者管理的本地服务。插件获得的是受作用域限制的客户端，不会获得原始 Socket、数据库连接、宿主路径或公网端口。

## 契约

运营者为已安装的插件实例创建绑定。Core 保存内部端点和凭据，校验插件声明的绑定名称，并统一施加来源、方法、重定向、请求体、响应体、并发、超时和取消限制。

插件通过 `network.request` 提交相对路径和有界请求数据，不能提交任意 URL、主机名、端口、Cookie、Authorization、Shell 命令或文件系统路径。绑定健康检查由 Core 有界执行，不会授予插件网络能力。

## 基础服务角色

| 角色 | 典型服务 | 边界 |
|---|---|---|
| `storage` / `webdav` | AList 或 rclone | Core 管理的媒体源或范围受限的管理桥 |
| `media-processing` | FFmpeg | Core 管理的探测、转封装、转码和点播 HLS 任务 |
| `network-egress` | Mihomo | 运营者策略和范围受限的控制 API 访问 |
| `archive` | 7z 兼容组件 | Core 管理的归档任务，不是插件命令执行 |

这些是兼容角色，不表示每个平台都已随项目发布对应二进制。安装、签名、摘要、健康和平台支持是独立门禁。

## 示例和限制

`alist-web-bridge` 与 `mihomo-web-bridge` 是参考适配器，只转发已声明的相对路径和过滤后的请求头，不修改上游源码，不暴露凭据，也不宣称已经完整兼容 AList WebDAV 或 Clash Web UI。

远程 WebDAV 媒体源与 AList 管理桥是两种独立能力。Core 管理媒体源句柄、凭据注入、目录、探测、播放会话和 Range 读取。首版不包含写入、删除、上传、任意代理或自动发现局域网服务。
