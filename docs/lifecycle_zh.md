# 插件生命周期

Core 负责插件生命周期。插件由版本化包和有作用域的安装实例组成；Worker 不能自行决定是否公开、如何重启或删除数据。

## 状态与转换

```text
staged -> installed -> enabled -> draining -> disabled
                         |          |
                         v          v
                    uninstalled <- disabled
```

- **staged**：包文件尚未进入活动运行时，等待签名、摘要和 Manifest 校验。
- **installed**：受校验的包和安装记录存在，但路由不一定已启用。
- **enabled**：Core 可以启动声明的运行时，并且只公开声明的路由和已授予能力。
- **draining**：拒绝新工作，同时取消活动中的网关流、任务、浏览器会话和媒体会话。
- **disabled**：Worker 已停止、路由已关闭，安装数据保留。
- **uninstalled**：应用入口和运行时已关闭；插件数据保留，直到用户单独确认删除。

安装、启用、停用和卸载都是管理员操作。插件不能自行启用，也不能请求超过签名 Manifest 的能力。每个安装实例可以减少能力授权，但不能在不重新审核新包的情况下扩大授权。

## 健康与重启

Core 只启动已登记的运行时工厂或摘要已校验的组件。健康状态是有界值（`starting`、`healthy`、`stopping`、`failed`、`stopped`），并只提供重试元数据；不暴露命令行、宿主路径、凭据或上游异常原文。崩溃采用有界退避；反复失败的插件会停用，等待运营者处理，不会无限重启。

## 升级与回滚

升级会把新包放入独立暂存位置，校验签名、摘要、SDK 范围和 Manifest，再排空旧安装后切换逻辑入口。新实例通过健康检查前，旧包和数据不会删除。激活失败时保留旧安装并继续启用，同时写入脱敏审计事件。数据迁移按版本记录、按作用域执行且幂等；Core 不向插件提供 SQL 或数据库连接。

## 卸载与数据

卸载先排空并撤销该安装实例的任务、浏览器会话、凭据、媒体会话和服务绑定，然后关闭应用入口，但保留插件数据以便恢复和导出。删除数据需要单独的明确确认，并受 SDK 导出/删除契约限制。
