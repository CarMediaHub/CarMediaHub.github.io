# 备份与恢复

状态：v0 草案

Core 提供面向运营者的离线快照流程。创建快照前请停止 Core，确保 SQLite 主库及 WAL 旁车文件处于稳定状态。

## 创建快照

在 Core 仓库或部署镜像中执行：

```powershell
pnpm backup backup --data-dir .\data --output .\snapshots\cmh-01
```

快照只包含 Core 明确管理的状态：SQLite 数据库及旁车文件、部署服务密钥、已验证插件包和受管组件文件。清单会记录每个文件的大小和 SHA-256 摘要。

目标必须位于数据目录之外，且目标目录不能已经存在。Core 会先写入临时目录，所有文件和清单完成后才原子重命名。

## 升级前的数据库版本兼容性

更换 Core 版本或部署包前，请先停止 Core 并创建、校验快照。SQLite 会在兼容迁移完成后记录数据库 schema 版本；如果数据库声明的版本高于当前 Core 能理解的版本，Core 会拒绝启动，避免旧版本静默打开新数据。当前版本门禁不等同于完整的迁移台账、回滚流程或跨版本升级演练。

## 校验与恢复

恢复只允许写入新的目录：

```powershell
pnpm backup restore --snapshot .\snapshots\cmh-01 --data-dir .\restored-data
```

复制前，Core 会校验清单、受管路径白名单、每一级父目录、文件类型、大小和摘要。符号链接、路径逃逸、快照内部目标以及任何已存在的目标目录都会被拒绝。启动恢复后的部署前，请重新检查配置和凭据。

## 责任与限制

- 快照应存放在源数据目录之外，并按敏感凭据保护。
- 快照包含解密本地受保护状态所需的密钥，不是可以公开分享的导出文件。
- 当前流程是本地离线流程，不上传数据、不创建定时备份，也不提供在线热备份。
- schema 版本变更前的快照是恢复依据；版本门禁本身不会自动执行回滚。
- Docker 镜像构建、Native 安装器、跨平台恢复演练、保留策略和升级回滚仍属于独立发布门槛。
