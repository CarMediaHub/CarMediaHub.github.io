# 插件发布

状态：v0 草案

发布是可复现的打包操作，不是自动批准。包必须从干净检出、版本化 SDK、包内相对入口、本地化资源、许可证、校验和、SBOM 和签名发布记录构建。

当 Manifest 声明 `ui.entry` 时，最终分发包必须将该路径作为包内普通文件提供。发布前的包校验会拒绝缺失 UI 入口、符号链接、绝对路径以及越界路径。

## 包门禁

- 按 SDK 版本校验清单和声明的能力。
- 构建 Worker 或受信共享适配器，不能包含宿主路径或未经校验的下载可执行文件。
- 执行类型、契约、隔离、泄露、回滚和目录测试。
- 使用受信发布密钥生成包摘要、SBOM、provenance 元数据和签名。
- 只发布包和公开文档；凭据、Profile、日志和私有部署数据不得进入包。

仓库目录记录包路径、集成类型、目标类别、运行时、SDK 范围、许可证和上游分类，同时记录逻辑 `sourceKey`、迁移状态、实现方式和风险类别；打包门禁会强制校验这些字段与机器校验迁移矩阵一致，发生漂移就拒绝构建。签名发布记录另行将包摘要与 provenance 绑定到受信密钥。目录条目不证明上游网站可用。浏览器、外部网络、媒体提取和代理兼容插件在公开分发前必须通过额外评审。
