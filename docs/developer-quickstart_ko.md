# 개발자 빠른 시작

플러그인은 SDK 계약을 따르는 Worker입니다. 플러그인은 SDK를 통해 플랫폼 기능을 요청해야 하며 Core 데이터베이스, 브라우저 컨텍스트, 호스트 파일 시스템 또는 구성 요소 프로세스에 직접 접근해서는 안 됩니다.

## 개발 순서

1. 버전이 지정된 SDK 타입과 플러그인 계약을 읽습니다.
2. 안정적인 플러그인 ID, 버전, 런타임, 기능과 서비스 바인딩을 선언합니다.
3. SDK 컨텍스트로 로케일, ID 범위, 화면, 기록, 미디어, 작업과 데이터 기능을 사용합니다.
4. 플러그인 상태는 범위가 지정된 데이터 API에 저장하고 버전이 있는 마이그레이션을 제공합니다.
5. 거부된 기능, 사용자 격리, 취소와 재시작에 대한 계약 테스트를 추가합니다.
6. 카탈로그에 게시하기 전에 플러그인을 패키징하고 서명합니다.

## 반드시 지킬 경계

- 논리적 대상이나 서비스 바인딩이 있다면 원시 상위 URL을 받지 않습니다.
- Cookie, 브라우저 Profile, CDP 엔드포인트 또는 호스트 경로를 반환하지 않습니다.
- 특정 데이터베이스 엔진이나 운영 체제 환경 변수를 가정하지 않습니다.
- SDK가 전달하는 언어와 화면 설정을 플랫폼 컨텍스트로 취급하고 플러그인에서 중복 설정을 요구하지 않습니다.
