# 安全模型

状态：v0 草案

CarMediaHub 采用 capability-first 模型。插件只获得其安装实例获准的最小作用域句柄。Core 在每个受保护边界验证身份、策略、目标、作用域、资源限制、取消和审计状态。

## 默认规则

- 插件不拥有公网宿主端口。
- 插件不获得原始数据库连接字符串或管理员凭据。
- 插件不获得不受限制的文件系统、Shell、网络或浏览器 Profile 访问。
- 插件之间不隐式共享配置、数据、缓存、秘密、日志、任务或浏览器状态。
- 已安装部署运行不要求托管账号、中继或中心服务。

## 受管组件

受管组件二进制文件先进入部署内部的 staging 目录，Core 不通过宿主 PATH 发现它们。安装要求发布记录由运营者信任的 Ed25519 密钥签名；记录绑定组件、版本、平台、artifact 标识和 SHA-256 摘要。任一字段或签名与 staging 文件不匹配都会被拒绝。下载源、密钥轮换、健康检查和回滚仍属于部署运维能力，不属于插件能力。

## 插件发布物

安装隔离 Worker 要求插件包发布记录由运营者信任的 Ed25519 密钥签名。签名绑定 Manifest、签名者标识、staging artifact 标识和规范目录摘要。Core 只安装相匹配的 staging 目录，拒绝链接与不安全入口，并且仅保存用于重启恢复的相对验证包位置。包验证不同于能力授权或启动 Worker；媒体 Range/HLS、转码、升级与回滚目前尚未提供。

## 运营者责任

运营者控制管理端访问、用户账号、设备、公网入口、网络路径、存储、备份和插件授权。任何可选外部服务都必须说明哪些数据离开运营者控制的基础设施以及原因。

## 报告

安全报告应包含最小复现、受影响版本和影响描述。不得包含密码、恢复码、私钥、会话数据、浏览器 Profile、完整请求日志、个人媒体或机密 URL。
