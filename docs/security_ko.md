# 보안 모델

상태: v0 초안

CarMediaHub는 capability-first 모델을 사용합니다. 플러그인은 해당 설치에 승인된 최소 범위의 핸들만 받습니다. Core는 보호 경계마다 ID, 정책, 대상, 범위, 리소스 제한, 취소와 감사 상태를 확인합니다.

## 기본 규칙

- 플러그인은 공개 호스트 포트를 사용하지 않습니다.
- 원시 데이터베이스 연결 문자열이나 관리자 자격 증명을 받지 않습니다.
- 제한 없는 파일 시스템, Shell, 네트워크 또는 브라우저 프로필 접근을 받지 않습니다.
- 플러그인 사이에 설정, 데이터, 캐시, 비밀, 로그, 작업 또는 브라우저 상태를 암묵적으로 공유하지 않습니다.
- 설치된 배포는 호스팅 계정, 릴레이 또는 중앙 서비스 없이 실행할 수 있습니다.

## 웹 응답 보안

Core 진입점은 콘텐츠 유형 추측, 참조자와 브라우저 기능을 제한하고 프레이밍을 막는 응답 헤더를 설정합니다. Core가 소유한 페이지와 API에는 동일 출처 Content Security Policy도 적용됩니다. 플러그인 `/apps/*` 콘텐츠는 Core가 강제로 다시 쓰지 않고 플러그인이 관리하는 리소스 정책을 유지합니다.

## 관리형 컴포넌트

관리형 컴포넌트 바이너리는 호스트 PATH에서 찾지 않고 배포 내부 staging 디렉터리에 둡니다. 설치에는 운영자가 신뢰하는 Ed25519 키로 서명된 릴리스 레코드가 필요합니다. 이 레코드는 컴포넌트, 버전, 플랫폼, artifact 식별자와 SHA-256 다이제스트를 바인딩합니다. 어떤 값이나 서명이 staging 파일과 일치하지 않으면 거부됩니다. 다운로드 소스, 키 순환, 상태 확인과 롤백은 플러그인 capability가 아니라 배포 운영 기능으로 남아 있습니다.

Core는 관리형 컴포넌트를 시작하기 전에 등록된 SHA-256 다이제스트를 다시 확인하고 `shell:false`로 검증된 절대 파일만 실행합니다. 컴포넌트 인수, 실행 시간, 취소와 stdout/stderr 총량에는 제한이 있습니다. 플러그인은 명령, 실행 파일 경로, 환경 변수 또는 임의의 컴포넌트 인수를 선택할 수 없습니다.

## 관리형 미디어 루트

각 미디어 루트는 관리자가 명시적으로 선택합니다. Core는 선택한 경로를 배포 데이터에 암호화해 저장하고 접근 시 디렉터리와 파일 유형을 확인하며 심볼릭 링크를 무시합니다. API는 루트 ID와 불투명 미디어 ID만 제공하고 플러그인은 호스트 경로를 받지 않습니다. 제한된 재귀 인덱싱, 단기 재생 세션, Range 읽기, Core 관리 remux/트랜스코딩/HLS VOD 작업, 단기 범위 제한 변환 결과 읽기, 인증된 재생 라우트와 HLS asset 읽기는 제공되며 만료 결과와 세션은 Core 시작 시 정리됩니다. 영구 결과 URL, 썸네일과 재시작 간 캐시 복구는 아직 제공되지 않습니다.

## 플러그인 릴리스

격리 Worker 설치에는 운영자가 신뢰하는 Ed25519 키로 서명된 패키지 릴리스 레코드가 필요합니다. 서명은 Manifest, 서명자 ID, staging artifact ID 및 표준 디렉터리 다이제스트를 함께 바인딩합니다. Core는 일치하는 staging 디렉터리만 설치하고 링크 및 안전하지 않은 entry를 거부하며, 재시작 복구를 위해 상대 검증 패키지 위치만 저장합니다. 패키지 검증은 capability 부여 또는 Worker 시작과 별개이며, 미디어 Range, 제한된 Core remux/트랜스코딩/HLS VOD 실행과 인증된 단기 결과 재생을 제공합니다. 또한 단일 설치 인스턴스의 패키지 업그레이드에서 drain, 고정 health 검사와 실패 시 이전 Manifest 및 권한 복원을 수행합니다. 클러스터 전체 drain, 마이그레이션 실패 롤백과 배포 간 업그레이드 훈련은 여전히 릴리스 게이트입니다.

운영자는 관리 화면, 사용자 계정, 장치, 공개 진입점, 네트워크, 저장소, 백업과 플러그인 권한을 관리합니다. 선택적 외부 서비스가 있다면 어떤 데이터가 왜 운영자 인프라 밖으로 나가는지 명시해야 합니다.
