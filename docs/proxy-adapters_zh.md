# 代理兼容插件

状态：v0 草案

代理兼容插件是运营者授权的上游网站或协议的兼容边界，不等于允许发布通用代理。上游页面、脚本、重定向、Cookie、媒体域名和遥测都必须按不可信输入处理。

## 必须满足的边界

- 使用隔离 Worker 和已声明的最小主机或服务绑定。
- 只接受相对路径和已声明方法；重定向与响应限制由 Core 统一管理。
- Cookie 和 Authorization 只能留在 Core 的凭据引用中，明文不得返回给 Worker 或客户端。
- 改写或移除会绕过 CarMediaHub 路由的外部导航、运行时资源地址、遥测、热链检查和媒体域名。
- 任何公开分发前都必须具备站点级泄露和回滚测试。

适配器不得暴露代理 token、面板域名、本地地址、浏览器 Profile、CDP 地址或任意上游 URL。页面虽然显示成功，但浏览器仍直接访问外域时，仍然视为契约失败。

## 发布策略

当前公开目录只包含中性适配器示例和本地服务桥。`proxy-compat-contract-example` 用于演示相对路径校验、请求/响应头过滤、重定向抑制和响应体大小限制，不命名或连接真实网站。BBC、YouTube、Jable、Pornhub 等旧 `site_gateway` 上游适配器在授权、泄露、兼容性和维护评审完成前只保留为非公开迁移元数据。已废止条目只用于审计，不复制进公开插件集合。

## 更安全的替代方案

运营者管理的 AList、rclone 或 Mihomo 优先使用 Core 服务绑定；受控播放优先使用自实现媒体插件；浏览器会话契约只用于不透明、有界的会话，不暴露 Cookie、Profile、任意导航或脚本执行。
