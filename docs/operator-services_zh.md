# 基础服务与服务绑定

状态：v0 草案

CarMediaHub 将媒体和网络工具视为由运营者控制的基础服务。服务可以与 Core 部署在同一主机，也可以由运营者管理的其他主机提供；插件通过受控的服务绑定访问它们，不为每个插件单独开放公网端口。

## 基础服务角色

- **AList**：为运营者管理的存储提供文件目录和 WebDAV 能力。
- **rclone**：挂载或统一不同存储提供商，并为兼容服务提供受控的 WebDAV 端点。
- **FFmpeg**：为媒体探测、封装转换以及后续播放流水线提供处理能力。
- **Mihomo** 及同类网络工具：由运营者自行管理的网络服务，Core 不预设路由策略。
- **Nginx 或等价网关**：可以用于路由内部组件流量，但不是每种部署都必须使用，也不会要求每个插件占用一个公网端口。

这些服务属于兼容目标和受管依赖。CarMediaHub 不修改上游源码；兼容插件通过 Core 的服务绑定 API 适配它们，使客户端能够从统一入口使用相关能力。

Core 组件目录会记录受限角色，用于选择和安装前校验：存储服务、WebDAV、媒体处理、归档和网络出口。角色只是元数据，不表示项目已经包含或安装了签名二进制；版本、平台、摘要、签名和健康检查仍是独立门禁。

公开的 `alist-web-bridge` 参考适配器展示了这一边界。它使用运营者批准的 AList 绑定，只接受有界相对路径并转发经过过滤的请求头；`GET`/`HEAD` 可读取相对资源，`POST` 只允许 `/api/fs/list`、`/api/fs/get` 和 `/api/fs/search`，JSON 请求体上限为 64 KiB。它不包含 AList 地址、凭据、Cookie 或上游源码。该示例用于说明契约，不代表已经兼容 AList 的所有 WebDAV 或管理功能。

公开的 `mihomo-web-bridge` 参考适配器以同样方式连接运营者批准的 Mihomo 控制 API，只开放 `/configs`、`/proxies`、`/providers`、`/rules`、`/connections` 和 `/version` 等受限路径。首版不转发认证头、不提供 WebSocket 流量面板，也不修改 Mihomo；它是控制 API 兼容示例，不代表完整 Clash Web UI 已完成兼容。

## 远程媒体源

AList 和 rclone 的 WebDAV 将来可以作为只读媒体源使用，但这与 AList Web 管理桥是两种不同的能力。规划中的实现会使用 Core 管理的不透明媒体源句柄，提供受作用域限制的目录、探测、播放会话和 Range 读取。插件不会获得 WebDAV URL、服务端点、宿主路径或凭据；WebDAV 凭据由 Core 在最后一跳解析和注入。

Core 已提供远程媒体源的注册、持久化、撤销和只读 provider fixture；当前 WDR 仍消费 Core 管理的本地媒体根目录，`alist-web-bridge` 仍是范围受限的管理/目录兼容适配器。真实 AList/rclone 部署矩阵、生产健康检查和 WDR 迁移仍未完成。首版不包含 WebDAV 写入、删除、上传、任意代理或自动发现。

## 绑定模型

运营者可以为某个已安装的插件实例配置绑定。绑定包含服务标识和内部上游地址，并由 Core 统一施加健康检查、请求和响应大小限制、并发限制以及重定向限制。插件拿到的是受能力范围约束的客户端，不会拿到原始数据库连接、任意命令执行能力、宿主环境变量或不受限制的网络套接字。

绑定不是自动发现机制。Core 不扫描局域网，不从 `PATH` 推断服务位置，也不会隐式读取系统环境变量。运营者需要通过管理端或部署配置显式提供服务端点和凭据；密钥始终处于 Core 管理的凭据边界内。

## 典型媒体链路

```text
浏览器或车机客户端
  -> CarMediaHub 单一入口
  -> 插件路由
  -> 受控服务绑定
  -> 运营者管理的 AList/rclone/媒体服务
```

Core 可以通过健康的受管 FFmpeg 组件执行有界的转封装/转码和点播 HLS 任务；Worker 和 Native/Docker 服务运行器仍属于独立的分发门槛。当前契约不表示已经提供直播 HLS，也不表示所有平台都已随项目发布 AList/rclone/Mihomo 二进制。

## 运营边界

- 绑定作用域限定为一个安装实例和一个插件实例。
- 健康检查必须使用明确的安全端点；重定向和响应大小受到限制。
- 绑定失败以稳定诊断码反馈，不向客户端暴露上游路径或密钥。
- 运营者负责上游服务的许可、凭据、网络策略、存储权限和安全维护。
- 必需绑定不可用时，插件必须给出清晰的降级状态。

## 当前状态

Core 的服务绑定 API、安装实例隔离、健康检查、请求/响应/并发限制和管理端表示已经实现并通过测试。真实第三方二进制的 Native/Docker 分发、平台级恢复以及生产级媒体流水线仍属于计划工作，具体门槛以治理仓库总计划为准。
