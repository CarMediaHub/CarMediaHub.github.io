# 文档站地图

状态：v0 草案

`CarMediaHub.github.io` 是整个项目的公开窗口。它在同一套文档体系中服务不同读者，同时保持产品承诺、部署边界、SDK 契约和安全规则一致。

## 按读者进入

| 读者 | 建议入口 | 主要问题 |
|---|---|---|
| 普通用户 | [项目由来](project-origin_zh.md)、[项目目标](project-goals_zh.md)和用户指南 | CarMediaHub 是什么、能做什么、运营者需要准备什么？ |
| 部署运营者 | [基础服务与服务绑定](operator-services_zh.md)、[备份与恢复](operator-backup_zh.md)及部署与运维指南 | 如何安装、加固、连接服务、备份、升级和诊断？ |
| 插件开发者 | [插件契约](plugin-contract_zh.md)和 SDK 参考 | 如何开发、隔离、测试、发布和维护插件？ |
| 贡献者 | 治理与工程参考 | 如何评审、发布、记录和支持变更？ |

## 规划中的栏目

逐页计划和页面状态由治理仓库的公开站内容清单维护；本站页面会从用户、运营者、开发者、参考和社区五个分区逐步展开。

```text
用户
  概览 -> 项目由来 -> 目标与边界 -> 安装 -> 首次配置
  -> 日常使用 -> 媒体播放 -> 故障排查 -> 隐私与责任

运营者
  系统要求 -> Docker -> Native -> 网络入口 -> [服务与绑定](operator-services_zh.md)
  -> [配置](operator-config_zh.md) -> [备份与恢复](operator-backup_zh.md) -> 升级 -> 诊断
  -> 认证 -> 备份恢复 -> 升级 -> 诊断

开发者
  SDK 快速开始 -> Manifest -> 生命周期 -> 上下文与国际化 -> 能力
  -> 数据与任务 -> UI -> 代理兼容插件 -> 自实现插件
  -> 测试 -> 打包、签名与安全报告

参考
  API -> 错误 -> 事件 -> 配置 -> 兼容矩阵
  -> 已知限制 -> 版本与迁移
```

公开站点说明受支持的行为和用户责任。私有实现笔记、部署秘密、内部路径和未完成的产品实验不放入本站。
