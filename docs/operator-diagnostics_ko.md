# 진단과 문제 해결

관리 화면에서 문제가 Core, 플러그인, 관리형 구성 요소, 상위 바인딩 또는 클라이언트 브라우저 중 어디에 속하는지 확인합니다. 영향이 작은 검사부터 시작하고 모든 보고서에 배포 버전을 기록합니다.

## 상태 확인

- **liveness**: Core 프로세스가 응답합니다.
- **readiness**: 데이터베이스와 시작에 필요한 상태가 준비되었습니다.
- **구성 요소 상태**: 등록된 관리형 구성 요소가 다이제스트와 상태 검사를 통과했습니다.
- **플러그인 상태**: 제한된 상태와 재시도 횟수만 표시하며 Worker 명령줄이나 호스트 경로는 표시하지 않습니다.

Core가 정상이어도 상위 저장소, 네트워크 바인딩 또는 차량 브라우저가 모든 파일을 재생한다는 뜻은 아닙니다.

## 브라우저 브리지 확인

관리자는 등록된 논리 브라우저 대상과 정규화된 HTTPS Origin을 확인할 수 있습니다. 브라우저 작업은 세션 활성, 플러그인 기능 권한, 대상 등록, 정상 브라우저 구성 요소, 마지막으로 결과 또는 취소 상태 순서로 확인합니다. 만료된 세션과 결과는 재사용할 수 없습니다.

## 미디어 확인

재생을 다시 시도하기 전에 미디어 소스, 재생 세션과 사용 가능한 모드를 확인합니다. `direct-range`, 리먹스와 트랜스코드는 서로 다른 기능입니다. 모드가 없다는 것은 호환성 제한이며 로컬 명령이나 임의 URL로 Core를 우회하면 안 됩니다.

## 보고와 개인정보

Core, 플러그인과 구성 요소 버전, 안정적인 진단 코드, 배포 대상과 타임스탬프를 포함합니다. Cookie, Token, 자격 증명, 브라우저 Profile, 절대 경로, 상위 URL과 개인 콘텐츠를 식별하는 파일명을 제거하십시오. 브라우저 Profile이나 제한 없는 디버그 아카이브를 첨부하지 마십시오.
